# AGENTS.md — instructions for coding agents working in this repository

This file is for AI coding agents (Claude Code, Copilot, Cursor, etc.) and for humans who want the same
ground rules. Read it before changing anything.

## What this repo is
A 4-day workshop, *Evaluating Autonomous Agents: Systems, Harnesses & AWS Production CI/CD*, built around one
running example: **Stockroom**, an inventory/order-support agent. Participants clone it; instructors teach from it.
The thesis is *Agent = Model + Harness*: most production failures live in the harness and the environment, so the
eval suite exercises tool selection, arguments, trajectories, guards, context compaction and injection handling,
not only final answers.

## Non-negotiable rules (from the project brief)
1. **Offline-first.** Everything (`make test`, `make notebooks`, `make ci`) must run with no AWS credentials and no
   network, using `FakeBedrockClient` and `FakeJudge`. Live AWS is opt-in via `STOCKROOM_MODE=live`.
2. **No hardcoded model IDs.** Read `AGENT_MODEL_ID`, `JUDGE_MODEL_ID`, `AWS_REGION` from the environment
   (`src/stockroom/config.py`). Defaults for live mode are documented in the README, never baked into code paths.
3. **Verify APIs, don't recall them.** Before using DeepEval, RAGAS, Promptfoo, the MCP SDK, Phoenix, Bedrock or
   AgentCore APIs, check the installed package (`uv run python -c "import x; help(x)"`) or the current docs. Record
   version pins and any deviation from the brief in `docs/DECISIONS.md`.
4. **Judges run on Bedrock, never OpenAI.** No `OPENAI_API_KEY` anywhere. DeepEval and RAGAS are wired to
   `stockroom.evals.judge` (Bedrock in live mode, deterministic fake in mock mode).
5. **No fabricated facts** in lectures, slides or docs: no invented incidents, companies, dollar figures or stats.
   Post-mortems are labelled composite/hypothetical, or real with a source link.
6. **No stubs.** No `pass`, `...` or `TODO` in delivered code. `TODO` is allowed only inside participant exercise
   cells in `notebooks/src/*.py` (tagged `exercise`), which must have a matching `solution` cell.
7. **Security/cost hygiene.** CI uses GitHub OIDC → IAM role (`docs/aws/`). Live mode enforces `MAX_TOKENS`,
   `MAX_STEPS`, `TOKEN_BUDGET` and prints an estimated cost. Never create AWS resources or incur spend without an
   explicit human go-ahead.

## Commands
| task | command |
|---|---|
| install | `make setup` |

## Layout cheatsheet
- `src/stockroom/config.py` – env-driven settings, mode detection, weakness flags.
- `src/stockroom/agent/` – `tools.py`, `bedrock_adapter.py` (live + fake), `harness.py`, `mcp_client.py`.
- `src/stockroom/evals/` – `metrics.py`, `judge.py`, `calibration.py`, `otel_tracer.py`, `rubrics/`.
- `src/stockroom/mock_server/mcp_inventory_server.py` – MCP server (official `mcp` SDK v2).
- `data/` – catalogue, orders, policy docs (one contains a seeded injection), golden set, calibration set.
- `tests/` – unit tests, guard tests, seeded-weakness tests, trajectory regression (writes `reports/eval_results.json`).
- `scripts/` – data validation, notebook builder, threshold gate, S3 sync, Promptfoo provider.
- `notebooks/src/*.py` are the source of truth; `.ipynb` files are generated by `make build-notebooks`.
- `eval_thresholds.yaml` is the single place thresholds live; `reports/baseline/main.json` is the committed main baseline.
- `package.json` / `package-lock.json` pin the Node tooling (Promptfoo, Marp); `make setup` runs `npm ci`.
- `lectures/`, `slides/`, `docs/INSTRUCTOR_GUIDE.md` are checked by `scripts/check_lecture_refs.py`: cite paths as `src/stockroom/...py` and symbols as `name()`.

## Conventions
- Python 3.12, `uv`, `ruff` (line length 100), type hints on all public functions, pydantic models for data that
  crosses a boundary, dataclasses for internal config.
- Seeded weaknesses are **feature flags** (`STOCKROOM_WEAKNESSES`); the shipped default is all-fixed so CI is green.
  Do not "fix" a weakness by deleting the flagged branch — the Day 3 lab depends on it.
- Keep the mock path deterministic: fixed seeds, scripted fakes, `chars/4` token estimates.
- When you change a metric, rubric, tool description or golden case, run `make test` then `make baseline` and
  explain the baseline diff in the PR.
- Numbers quoted in teaching materials must be reproduced from the repo in mock mode (they are upper
  bounds); never paste figures from memory or the web.
- Finished a work session? Update `docs/TASKS.md` (and `docs/DECISIONS.md` for any deviation) before you stop.
